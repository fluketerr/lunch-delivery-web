# งานที่เหลือ เอาไปแบ่งกันทำได้เลย

ตอนนี้มีหน้าเว็บแล้ว ลูกค้ากับออเดอร์เริ่มดึง API และแสดงหมุดได้ ส่วนจัดเส้นทางกับใบงานไรเดอร์ในหน้าหลักยังใช้ข้อมูลตัวอย่างอยู่ แต่ตรวจ Backend ที่ `C:\1-69\A-Web\lunch-delivery-api` เมื่อ 20 ตุลาคม 2569 แล้ว พบว่ามีตัวคำนวณ ค่าส่ง และ API ใบงานแล้ว งานต่อไปเน้นต่อหน้าเว็บกับของที่มีอยู่

**Backend ทำส่วนคำนวณไว้แล้ว ไม่ต้องเริ่มเขียนใหม่** อยู่ที่ `service/delivery-planning.ts` และเรียกผ่าน POST `/job-sheets/preview`

- [x] Backend แบ่งงานไม่เกิน 3 ออเดอร์ต่อคน ครอบคลุมทุกออเดอร์ที่เลือกโดยไม่ซ้ำ
- [x] Backend ขอระยะทางถนนจาก OSRM และคำนวณลำดับส่ง ตรวจระยะร้านถึงลูกค้าไม่เกิน 3 กม.
- [x] Backend คำนวณเวลา ค่าเริ่มต้นคือ 30 กม./ชม. ออก 11.30 น. ส่งมอบเสร็จไม่เกิน 12.30 น. และเผื่อเวลาส่งจุดละ 2 นาที ปรับค่าได้
- [x] Backend เลือกแผนตามค่าส่งและขอทางเลือกอื่นได้ ถ้าพิกัดผิดหรือจัดไม่ได้จะตอบรายละเอียดปัญหา
- [ ] ต่อหน้าเว็บให้เลือกวัน ออเดอร์และพิกัดร้าน แล้วเรียก API แทนข้อมูลตัวอย่าง
- [ ] ลองกับ API และฐานข้อมูลทดสอบจริง พร้อมเช็กว่ากติกาที่ตั้งตรงกับโจทย์

ตัวค้นหาแผนจำกัดประมาณ 1.5 วินาทีหรือ 40,000 ขั้น จึงไม่รับประกันว่าทุกครั้งจะได้ต้นทุนต่ำที่สุด ต้องแสดงข้อความวิธีค้นหาที่ Backend ส่งกลับมาด้วย

จำไว้ว่า **3 ออเดอร์ต่อไรเดอร์ ไม่ใช่ 3 กล่อง** เช่น 3 ออเดอร์ ออเดอร์ละ 3 กล่อง รวม 9 กล่องก็ยังอยู่ในเงื่อนไข

## 7 Backend และฐานข้อมูล

ตรวจ source Backend แล้ว มีส่วนหลักตามนี้

- [x] API อ่าน เพิ่ม แก้ ลบลูกค้า รวมถึงค้นหาและหาลูกค้าใกล้พิกัด
- [x] API อ่าน เพิ่ม แก้จำนวน ลบและจำลองออเดอร์ 20 ถึง 30 รายการ
- [x] API เลือกวัน เลือกออเดอร์ คำนวณแผน ยืนยัน และขอเส้นทาง GeoJSON
- [x] โค้ดบันทึกใบงานและจุดส่งใน transaction มี snapshot แผนและตรวจข้อมูลเปลี่ยนก่อนยืนยัน
- [x] API เปิดใบงาน เริ่มงานและส่งสำเร็จ พร้อมบันทึกเวลาจริง
- [ ] ติดตั้ง dependencies ให้ครบ ตอนตรวจ `cors` และ `@types/cors` ยังไม่มีใน node_modules ทำให้ typecheck และชุดทดสอบ API ติด
- [ ] เช็ก schema ฐานข้อมูลจริง มีตาราง customers orders job_sheets job_stops และข้อบังคับ UNIQUE ตามที่โค้ดคาดหรือยัง ไฟล์ migration ที่พบเพิ่มคอลัมน์ให้ตารางเดิม ไม่ได้สร้างฐานข้อมูลใหม่ทั้งหมด
- [ ] เช็กว่ารัน migration เพิ่ม planning_data และเวลาเริ่มหรือส่งเสร็จแล้วหรือยัง จากนั้นลอง flow กับฐานข้อมูลทดสอบ
- [ ] แยกข้อมูลที่ส่งให้ไรเดอร์ ตอนนี้ API เปิดใบงานยังส่งต้นทุนและกำไรร้านออกมาด้วย
- [ ] ตั้ง API ฝั่งเว็บให้ชี้ Backend เวอร์ชันนี้ อย่าถือว่าโค้ดในเครื่องถูก deploy ไป Render แล้ว

ตัวอย่างแผนก่อนยืนยันเก็บในหน่วยความจำ 30 นาที หาก Backend restart ต้องคำนวณใหม่ ส่วนใบงานที่ยืนยันแล้วมีโค้ดบันทึกลงฐานข้อมูล

เอกสาร Backend อ้างถึงหน้า `/test-api` แต่ไม่พบหน้าและ route นี้ในเว็บโฟลเดอร์ปัจจุบัน ให้ต่อกับหน้าหลักหรือเช็กว่าหน้าทดสอบอยู่ branch อื่น

## 8 ลองระบบรวมและเตรียมส่ง

- [ ] ลองตั้งแต่เพิ่มลูกค้า สร้างออเดอร์ คำนวณ ยืนยัน แล้วเอาเลขใบงานไปเปิดหน้าไรเดอร์

- [ ] ลองเปิดหน้าไรเดอร์บนมือถือ และกดลิงก์แผนที่ทุกจุด
- [ ] แก้ทางเข้าหน้าเจ้าของ ตอนนี้ใช้ key ที่ฝังใน frontend และเปิด URL เจ้าของได้ตรงๆ
- [ ] ลอง production build ใหม่ ตอนตรวจติดการดาวน์โหลด Google Fonts ส่วน development build กับ tests เดิม 9 รายการผ่านแล้ว

ผลตรวจ Backend ล่าสุด: tests ส่วนคำนวณผ่าน 16 รายการ ส่วน tests API แบบ mock 2 ไฟล์ยังรันไม่ได้เพราะขาด cors และ typecheck ติดสาเหตุเดียวกัน ยังไม่ได้ทดสอบฐานข้อมูลหรือ OSRM จริง และไม่ได้รัน tests ที่เพิ่มหรือลบข้อมูลในฐานข้อมูล

## เริ่มทำอะไรก่อน

เริ่มแก้ dependencies และเช็กฐานข้อมูล Backend ให้รันได้ก่อน จากนั้นแบ่งคนแก้หน้าลูกค้าและต่อปุ่มออเดอร์ อีกคนต่อหน้าจัดเส้นทางกับ API ที่มีแล้ว และอีกคนต่อหน้าไรเดอร์ สุดท้ายลองระบบรวม ไม่ต้องเริ่มเขียนตัวคำนวณเส้นทางหรือค่าส่งใหม่

ถ้าต้องตัดงานให้ทันส่ง ให้เน้น **คำนวณเส้นทางจริง แสดงเวลาและกำไรจริง และเปิดใบงานจริง** ก่อน ส่วนเพิ่มลบลูกค้าให้เช็กขอบเขตกับอาจารย์ เพราะโจทย์เขียนรวมๆ ว่าจัดการข้อมูลลูกค้า และไม่ต้องเพิ่ม GPS ติดตามสดหรือระบบชำระเงินเพื่อให้ครบโจทย์
